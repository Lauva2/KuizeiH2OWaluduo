# 木筏漂流经营游戏

面向 PC 的上帝视角轻松经营游戏。玩家从一个人的小木筏开始，通过收集、生产、自由扩建和招募船员，逐步建立舒适的海上小社区。

本文记录已讨论的设计方向，作为后续原型和内容制作的依据。除“当前实现”中明确列出的内容外，文中玩法属于计划内容。游戏名称尚未确定。

## 项目基础

- 引擎：Unity 2022.3.62f2。
- 目标平台：PC。
- 主要操作：鼠标下达指令，键盘辅助操作。
- 当前阶段：土豆种植、自动浇水收获与烤土豆，装饰与营地舒适度、床铺与自动休息、救生筏招募第二名船员、独立生活需求与工作分工、收集网与自动收取、设施选中/搬移/拆除、海中鱼群与昼夜光照、混合钓获、随机漂流补给、图纸发现与分类建造、钓鱼烤鱼、净水饮水、时间控制与本地存档原型。

## 当前实现：木筏经营、轻量需求与自动施工

打开 `Assets/Scenes/RaftPreview.unity` 后点击 Play，即可规划扩建、标记漂浮物，并让开局船员自动打捞和施工。开局提供一根鱼竿，前期依靠钓鱼和漂流补给获得食物、建材与瓶装淡水。净水器需要先从漂流补给箱发现图纸，再准备材料施工。按 `B` 打开分类建造图册，分类内只显示已解锁配方；选择卡片进入放置。空格暂停，数字 `1 / 2 / 3` 切换 `1× / 2× / 4×`；`F5` 保存、`F9` 读档。材料不足时蓝图等待，补料后自动继续。配置读取、系统初始化和更新由 `GameManager` 统一组织。

- 起始木筏为 3 × 3 块甲板，每格 2 米；模型包含倒角木板、圆木浮筒、绳索和钉子。
- `BuildManager` 管理网格占用、已建甲板、待施工蓝图及施工状态。
- 支持沿现有甲板或蓝图的四边连续扩建；禁止重叠、仅对角连接和超出规划范围的放置。
- 预览有效时为绿色，无效时为红色；放置后的蓝图为蓝色。
- 支持撤销尚未完工的蓝图，包括船员正在前往或正在施工的目标；如果撤销会让其他蓝图失去与已建木筏的连接，需要先撤销外围蓝图。
- 放置蓝图不扣材料；船员到达施工点、准备开工时预留材料，完工时从库存总量结算，取消或中断施工时释放预留。
- 船员已接入 `TryBeginConstruction` / `TryCompleteConstruction` 与 `Planned → Constructing → Complete` 状态，按时间推进施工。开始施工要求相邻格已有正式甲板，船员始终站在正式甲板上工作。
- 经营暂停时仍可规划。甲板使用固定高度，保持建造视野稳定。

### 物资与打捞

- `ResourceManager` 管理木材、废料、鲜鱼、熟鱼、淡水、土豆、烤土豆七种资源的总量、预留量与可用量，始终满足“总量 = 可用 + 预留”。所有原料和产物使用同一套归属、溢出检查与原子结算；预留归属于具体蓝图或工作任务，重复结算或释放不会重复增减库存。
- 当前测试数值：开局 8 木材、2 废料、2 份可留种的土豆；每块甲板消耗 4 木材、1 废料；一捆漂浮木材提供 2 木材，一箱漂浮废料提供 1 废料。
- `SalvageManager` 按变化的海流从木筏上游及两侧随机生成木材、废料、水瓶与补给箱，起始最多 3 件。生成位置依据已建甲板范围、海流方向及随机间距计算，避免固定航道与物资重叠。
- 退出建造工具后，点击漂浮物标记打捞，再次点击取消；金色圈表示已经标记，不代表物资当前一定够得着。
- 船员只能从可达的已建甲板边缘打捞。默认距离以甲板格中心计算，水平距离不超过 2.8 米，打捞用时 1.2 秒，不会下水或穿过海面。
- 物资保持漂流；太远的标记会等待物资靠近，物资漂出范围、失效或标记被取消时，船员安全释放任务并重新选择工作。
- 成功打捞后物资直接进入公共库存，漂浮物被移除；领取和收集均检查任务归属与范围，防止重复入库。
- 默认漂移基准速度 0.35 米/秒，每件乘以 0.75～1.25 的随机速度；方向取随时间转动的海流、风向和局部扰动，水瓶更容易受风影响。UI 用箭头显示海流和风向。
- 补给刷新间隔为 16 秒 ±35%，常规场上最多 7 件；类型权重为木材 35%、废料 20%、水瓶 20%、补给箱 25%。物资存活 85 秒，过期或漂入已建甲板下方时清理，不计入库存。
- 打捞水瓶获得 1 淡水。补给箱打捞后自动打开，获得 2 淡水（45%）、3 木材（30%）或 2 废料（25%），并额外获得 1 份土豆，可用于留种；原有抽取顺序与随机状态保持不变。同时有 12% 概率发现海水净化器图纸，最迟第 6 个箱子必定发现。图纸永久解锁，不重复发放；发现时提示按 `B` 查看。
- 暂停时漂流和打捞进度停止，仍可标记物资、规划或撤销蓝图。点击检测同步移动物体的碰撞体位置，避免视觉位置与点击位置不一致。

这些数值可通过配置调整，尚未做最终平衡。当前不包含仓库容量、搬运到独立仓库或水域专属掉落。

### 收集网与自动收取

- 漂流收集网开局即可在 `B` → 生产设施中建造，也可按 `N` 进入放置工具。占一格已建甲板，消耗 **6 木材 + 2 废料**，使用现有蓝图、预留和船员施工流程；开局不免费附送设施。
- 网篮伸向外侧海面，绿色操作位位于内侧甲板。`R` 每次旋转 90°；网口对应的海面格必须为空，不能有甲板或蓝图，也不能与另一张网共用网口。扩建不能封住现有或已规划的网口，需要先搬移/撤销收集网。
- `CollectionNetManager` 由 `GameManager` 读取配置并初始化，接入 `SalvageManager` 漂流更新。物资经过网口前一格海域时自动被拦截，无须手动标记；使用移动线段检测，避免较大时间步跨过网口，也不会隔着甲板捕获远侧物资。
- 每张网最多暂存 **4 件**，支持木材、废料、水瓶和补给箱。满网停止捕获，第 5 件继续漂流；入网物资从漂浮物列表移除，停止漂流与过期计时，尚不进入公共库存。
- 已标记或正在被领取的漂浮物也可入网，原打捞任务随之失效并安全重新调度，不会重复收集同一件物资。物资入网不消耗掉落随机状态，不推进图纸保底。
- 船员自动到相邻操作位逐件收取，默认每件 1.2 秒，受工作效率影响；满网优先于未满网，同状态下选择最近可达操作位。木材/废料保留捕获时的数量，水瓶提供 1 淡水，补给箱在实际收取时才按现有掉落表结算物资与净水器图纸。
- 暂停停止漂流捕获、收网进度与动作。饮食需求、搬移及取消任务会释放领取权；未完成的一件保留在网中，重新收取从零计时。库存无法接收时保留物资，补给箱失败结算也不会消耗随机状态或图纸保底。
- 木框与绳网模型带 4 个暂存展示位，显示实际捕获的物资模型；容量小旗以绿色/满载暖黄色区分状态，收取时显示角色动作与进度条。主 HUD 显示收集网数量。
- 点击收集网沿用 `UICommon_Facility`：显示暂存数量、满载状态、物资类型与船员工作；不显示烹饪/净水的目标库存按钮。网中有物资时需先由船员收空后再拆除；空网按原建造用料全额返料。
- 免费搬移及旋转会连同暂存物资一起移动，预览期间暂停捕获；取消后保留原位并恢复使用。存档保存每张网的暂存类型、数量和顺序；搬移预览保存原位置，读档恢复物资模型并清理领取权，不重复发放奖励。
- 收集网暂存字段为可选，兼容原有无收集网的版本 1/2 存档。读取时额外拒绝超过 4 件、负数量、未知物资、未完工网中存货、非收集网藏货和网口被封堵等数据。

可先建烤架改善食物供应，也可先建收集网改善采集。开局材料足够建造其中一项，后续通过打捞、收网与钓获继续补料。当前网口捕获范围是网前一格海域，放置时可结合海流方向调整布局。

菜单 `Tools > Raft Game > Add Collection Nets` 添加配置、模型、场景绑定及图册卡片，重复执行保留已有配置和起始木筏布局；批处理入口 `RaftGame.Editor.CollectionNetSceneBuilder.InstallAndBuildContent` 同时构建 AA 内容。

### 开局鱼竿与钓鱼

- 每次新开局默认持有 1 根鱼竿、0 条鲜鱼；`FishingManager` 管理鱼竿使用权与每次垂钓，鲜鱼通过 `ResourceType.Fish` 单独入库，不会算作木材或废料。
- 默认开启“空闲钓鱼”。船员没有可执行的饮食、打捞、收网、施工或生产任务时，沿已建甲板寻路到最近的空闲边缘，朝海面抛竿。
- 钓位必须在可达的已建甲板上，前方相邻水域不能有正式甲板或蓝图；规划到当前抛竿水域时会收竿换位。
- 默认每次垂钓 6 秒，基础掉落权重为鲜鱼 55%、瓶装淡水 25%、木材 12%、废料 8%；分别获得 1 鲜鱼、1 淡水、2 木材或 1 废料。最多连续 5 次没有水瓶，第 6 次保证钓到水瓶。不消耗建材、鱼饵或鱼竿耐久；这些是可调整的原型数值。
- 垂钓时显示手持鱼竿、连接竿尖与水面的鱼线、浮漂、角色持竿动作和进度反馈。
- 默认“自动”偏好下，新增可执行的打捞或施工会打断钓鱼，包括前往钓位的行走；船员安全收竿后切换任务，忙完再自动继续钓鱼。“采集优先”会优先钓鱼，其余工作在空闲时补位。
- 未完成的一次垂钓不发放物品，也不推进掉落随机状态；完成的垂钓只结算一次。取消、关闭钓鱼或退出时归还鱼竿，同一根鱼竿不能重复领取。
- `F` 或“空闲钓鱼”按钮可随时开关自动垂钓；关闭时不影响已在执行的打捞和施工。暂停会停止钓鱼进度与浮漂动画。
- 鲜鱼进入公共库存，可供烤架生产熟鱼；尚未接入鱼种差异或鱼竿制作。

### 烤架、熟鱼与轻量饥饿

- 烤架占用一格已建甲板，造价为 4 木材 + 2 废料；通过蓝图和船员施工建成，使用现有施工时长。开局没有免费烤架或食物。
- `B` → 生产设施 → 简易烤架，或用 `G` 切换工具；`R` 每次旋转 90°。预览中的箭头和外框表示相邻操作位，该位置必须是空闲的已建甲板。
- 放置会检查现有与已规划烤架的占地，保留所有操作位，并确保建成后通路和已有甲板蓝图仍连通。不能建在水面、未完工甲板或其他设施上。
- 烤架蓝图尚未完工时仍可通行，建成后成为寻路障碍。船员站在指定相邻操作位施工和烹饪；不会穿过已建烤架，也不能在船员脚下完成设施。
- 尚未完工的烤架可用 `X` 撤销，保留甲板并释放预留材料；已建烤架支持点选、免费搬移与全额返料拆除，暂未接入升级。
- `ProductionManager` 管理自动烹饪：默认每批 **1 鲜鱼 + 1 木材 → 1 熟鱼**，标准效率下耗时 6 秒。到达操作位才预留原料，完成时原子结算原料与产物。
- 默认熟食目标库存为 4，按熟鱼与烤土豆合计计算，界面 `−` / `+` 可在 0～20 间调整；目标 0 停止接新批次，已经开工的批次可以完成。达到目标后停止烹饪，消费后再补充。烤鱼仍为 1 鲜鱼/1 木材 → 1 熟鱼，烤土豆为 1 土豆/1 木材 → 1 烤土豆，均默认 6 秒；原料可用时优先补充数量较少的熟食，两种熟食数量相同时优先烤鱼。
- 每名船员每次只操作一座烤架；不同操作位的两座烤架可同时生产，接单时计入正在制作的份数，避免两人重复补同一份库存。原料不足时不会开工。烹饪可以被偏好中更高优先级的可执行工作或饮食打断，取消后返还原料，重新开工从零计时。判断施工是否可执行时包含烹饪释放的材料，避免最后一块木材被低优先级工作占住。
- `NeedsManager` 管理每名船员独立的 `CrewNeeds`。饱腹初始 70，每秒下降 0.08；降到 55 或以下且库存有熟鱼或烤土豆时自动进食，优先熟鱼，耗时 2.5 秒，消耗 1 份熟食并恢复 35，最高 100。两人共享库存，但食物类型、预留、需求恢复及效率分别计算；生土豆不直接充当一餐。
- 饱腹度低于 25 时工作效率逐渐降低，最低 65%，影响行走、施工、打捞、钓鱼与烹饪。**不会因饥饿死亡**，饱腹度最低为 0，进食本身不受效率惩罚。
- 进食优先于工作；中断行走时先沿安全路段回到格子中心。开吃时预留熟鱼，吃完才扣除，取消或系统退出会返还尚未吃完的食物。
- 烤鱼时显示烤架上的鱼、暖光、夹子动作和进度；进食时显示手持熟鱼和进食动作。暂停会停止饱腹消耗和全部工作进度。
- 界面显示熟鱼库存、生产目标、已建烤架、饱腹度及工作效率，继续使用 `UICommon_Build` 的 MVC 和 AA 加载流程。

建议先建一座烤架体验闭环。开局建材足够建造烤架并烤 4 条鱼；净水器还需要发现图纸并继续收集建材。暂未接入食物腐败、仓储容量或搬运。

### 净水与轻量口渴

- 净水器开局锁定，只能通过漂流补给箱发现图纸；前期依靠钓鱼、水瓶和补给箱获得淡水。解锁后在 `B` → 生产设施中出现，占一格正式甲板，造价 **6 木材 + 3 废料**。`P` 是解锁后的放置快捷键，锁定时不能绕过图纸限制；`R` 旋转操作位。放置、施工、障碍与通路规则和烤架共用。
- `WaterManager` 默认每批 **1 木材 → 2 淡水**，标准效率耗时 8 秒。船员在相邻操作位开工时预留燃料，完成时一次结算；中断释放燃料，重做批次从零计时。
- 淡水默认目标为 4，可用图标下的 `− / +` 在 0～20 调整。目标是接单阈值，批次产量可能使最终库存略高于目标；目标 0 不接新批次，已开始的批次仍可完成。
- 水分开局 80，每秒下降 0.07；降到 55 或以下且有淡水时自动饮用。每次 2 秒、消耗 1 淡水、恢复 40，最高 100；饮用时显示杯子和动作。
- 饱腹、水分或精力低于 25 时工作效率逐渐降低。三个需求取较低效率，合计最低仍为 65%，不会死亡；吃饭、喝水和床上恢复精力本身不受效率惩罚。

### 已建设施的选中、搬移与拆除

- 退出建造工具后，左键点击已建设施或装饰：占地显示金色边框，功能设施的相邻操作位显示绿色边框，右侧打开设施面板。装饰保持通行，不占用额外操作位。点击空白处、关闭按钮或 `Esc` 取消选择；打开建造图册或其他建造工具也会结束设施操作。
- `FacilityManager` 管理选择、预览和操作状态，`BuildManager` 统一提交布局变化；系统由 `GameManager` 初始化和驱动。面板显示设施类型、原位置、操作位、当前工作、生产目标与拆除返料；目标按钮与主 HUD 共用同一生产设置。
- 点击“免费搬移”后，原设施保留在原位并暂停接单/拦截。船员立即取消该设施的生产、收网或前往任务，释放预留原料/领取权；行走中不会瞬移，而是沿安全路段返回格子中心。已完成的物资保留在公共库存，网内未收取的物资随网搬移。
- 搬移预览用绿/红区分有效位置，`R` 每次旋转 90°，左键确认后立即移动，无须重新施工、无需建材。允许原地旋转，也允许把原占地作为新的操作位。功能设施不能占用船员、其他物件及其操作位，也不能切断通路；可通行装饰允许放在船员所在格或功能设施操作位上，每格仍只容纳一个设施/装饰。
- 右键、`Esc` 或“取消搬移”保留原位置和朝向，设施恢复接受生产任务。确认新位置后，旧占地恢复通行；功能设施的新占地阻挡寻路，装饰的新占地保持通行。
- 点击“拆除返料”先显示确认状态，可选择“保留设施”。确认拆除后保留底下的甲板，取消该设施未完成的任务，返还**建造时实际支付的全部材料**；库存容量溢出时拒绝拆除，保留设施。重复点击或库存回调不能重复返料。
- 新存档记录设施位置、朝向及原建造用料；兼容缺少用料字段的旧档，旧设施以当前配置用料作为返料依据。搬移预览期间保存原位置；确认后保存新位置；读档清理选中状态与预览，不遗留暂停接单的设施。
- `UICommon_Facility` 使用现有 MVC、Common 层、`cache=true`，预制体位于 `Assets/Art/Prefabs/UI/`，AA 地址与预制体名一致，归入 `UI` 分组。关闭解除事件，缓存重开不会累加按钮监听；面板外保持世界交互，面板内拦截点击。窄窗口布局避开时间控制区。

菜单 `Tools > Raft Game > Add Facility Management` 接入场景和 AA 面板；重复执行保留已有木筏布局。批处理入口 `RaftGame.Editor.FacilitySceneBuilder.InstallAndBuildContent` 同时构建 AA 内容。

### 海中鱼群与昼夜

- 木筏周围有 4 小群、共 16 条水下游鱼，使用银绿、珊瑚金与蓝色三种配色。低多边形鱼身、侧鳍、背鳍和摆动的叉尾统一现有画风，各群沿不同路径游动。
- `OceanLifeManager` 按已保存的海浪时间计算鱼的位置、朝向、深度与摆尾；同一配置下可直接重建相同状态。银鱼、珊瑚鱼和蓝鱼分别使用 Blender 制作的流线、圆身、宽鳍轮廓，同种共享鱼身/鱼尾网格，统一使用水下材质与颜色属性块；鱼群作为海洋环境表现，钓鱼沿用当前混合掉落表。
- 鱼在实际海面下游动。鱼身受分区水色、水深吸色和昼夜亮度影响，叠加与海面相同的稀疏表层波纹。水面可见区域写入模板遮罩，鱼仅在这些区域呈现，已建木筏和设施会遮挡鱼身，木板缝隙保留水下可见性。鱼没有碰撞体，不会挡住漂浮物点击。
- `DayNightManager` 从现有 `TimeManager.ElapsedSeconds` 推导天数和时刻：默认 **10 分钟一天，08:00 开局**。HUD 显示天数、24 小时时刻、日进度与太阳/月亮图标。
- 日光、环境光、海水配色与反射平滑过渡；清晨和黄昏带暖色，夜晚保留蓝色月光，木筏角落的暖色灯笼自动亮起。夜间仍可打捞、钓鱼、规划与生产。
- 暂停同时冻结昼夜、海浪、鱼群与摆尾，倍速同步加快。存档沿用已有经营时间与海浪时间，读档立即还原昼夜、灯笼和鱼群，兼容版本 1/2，无须新增独立环境计时存档。
- `Tools > Raft Game > Add Ocean Fish and Day Night` 生成鱼和灯笼预制体、配置、场景绑定与时钟 UI；修改 UI 后需重新构建 AA。

### 经营时间与本地存档

- `TimeManager` 控制暂停和 `1× / 2× / 4×`。空格暂停/恢复，数字 `1 / 2 / 3` 切速度；点击速度按钮会继续经营。暂停停止船员、需求、海流和海浪，保留建造规划、标记打捞、UI 与相机操作。
- `F5` / “保存”写入手动档，`F9` / “读档”读取手动档；没有手动档时回退到自动档。`Shift + F9` 可直接读取自动档。启动时保留新开局，由玩家选择读档。
- 非暂停经营每 60 秒实际时间自动存档，退出时也自动保存。手动档与自动档分开，写入先经过临时文件，再原子替换，并保留上一版 `.bak`。
- 存档目录为 `Application.persistentDataPath/Saves`，文件为 `slot_01.json` 和 `autosave.json`。批处理验证改用验证副本的 `Temp/ValidationSaves`，避免覆盖玩家存档。
- 保存木筏格子、设施类型/朝向、未完成施工进度、库存总量、船员所在格、需求、储备目标、鱼竿/钓鱼开关、时间速度/暂停、海浪时间、漂浮物及相机位置；还保存图纸解锁、掉落/漂流随机状态和水瓶/图纸保底计数，读档后下一次掉落保持一致。读档时船员回到所在格中心；未完成的制水、烹饪、饮食和钓鱼任务重新调度，未结算原料仍在库存中。
- 当前存档版本为 6，可迁移版本 1～5。版本 1/2 恢复为一名船员、默认“自动”偏好，保留原位置、饱腹和水分，重新开始救援等待；版本 3 保留两人名册与偏好。版本 1～3 的精力使用当前配置初值，默认 85，尚无未完成休息意愿；版本 4/5 保留已有精力、床铺、休息意愿与装饰。旧档不会在每次读取时补发开局种薯，缺少土豆可从补给箱获得。旧档中已有或已规划的净水器会保留并解锁，既有漂浮物也不会因新的稀疏刷新上限被删除。
- 读档先检查版本、数值、类型、重复占地、操作位和连通性，再恢复运行状态；损坏或不兼容文件会提示失败并保留当前游戏。

### 船员行为

- 开局一名风格化船员“阿航”，救援后加入“小澜”，当前上限两人。`CrewManager` 统一管理名册、招募、任务及操作位领取，各 `CrewWorker` 持有独立位置、路径、工作与需求；角色动作和进度条由 `CrewView` 表现，第二人使用橙色上衣区分。
- `DeckPathfinder` 使用四邻格 BFS，只允许经过 `Complete` 且未被已建设施阻挡的甲板，不经过海面或未完工甲板蓝图。`HasDeck` 单独判断物理甲板覆盖，避免把烤架占地误判为水面。木筏扩建后可直接使用新甲板，无需烘焙 NavMesh。
- 所有偏好都先满足可执行的进食/饮水，再安排有床位的必要休息，然后接应已标记的救生筏。默认“自动”依次选择：玩家标记且可达的打捞 → 自动收网 → 有料可达的甲板/设施施工 → 制水 → 烤鱼 → 空闲钓鱼。两个饮食需求同时可满足时先处理数值较低者；收网先满网、再按操作位距离选择。生产和钓鱼会让位给当前偏好中更高优先级的可执行任务。
- 连续蓝图随前一块完工逐步变得可达；缺料蓝图等待补料，船员可在等待期间钓鱼，补料后自动重新检查。
- 移动速度默认 1.8 米/秒，单块甲板施工时间默认 4.5 秒；行走用时单独计算。
- 施工时显示挥锤动作、蓝图上方的进度条，以及面板中的船员状态和百分比；完工后蓝图替换为正式甲板并更新计数。
- 行走途中目标被撤销时，先沿当前安全路段回到甲板格中心，再重新选择任务；施工目标被撤销时不会继续生成甲板。
- 不可达任务进入“等待通路”，不会跨越海面；新增甲板或蓝图后重新检查，也会按配置间隔重试。
- `DeckCell.ConstructionProgress` 记录施工进度，`TrySuspendConstruction` 暂停任务并保留已有进度，后续可重新领取。
- 船员使用经营时间，暂停时移动、施工和动作均停止；UI 与相机仍可操作。

### 救生筏招募与两人分工

- 默认经过 45 秒经营时间，木筏附近出现一张载人的小救生筏；需要有空闲、连通的正式甲板供新人落脚。退出建造工具后点击救生筏标记，再次点击取消。标记后停留等候，船员从甲板边缘接应 3 秒，新人才正式加入；无需额外建材。
- 未标记救生筏按海流缓慢漂移（0.08 米/秒），180 秒后或漂到甲板下方时离开，30 秒后再次尝试出现。满员后停止出现。暂停冻结等待、漂流与救援，倍速同步加快；不能靠重复点击或读档重复招募。
- 按 `C` 或底部“船员”按钮打开 `UIPop_Crew`，查看每人的名字、饱腹、水分、效率、当前工作和甲板位置。面板为 Pop 层、`cache=true`，AA 地址与预制体名一致，归入 `UI` 分组；关闭和重开解除/恢复监听。打开时收起图册与设施选中，并拦截世界操作；`C` / `Esc` / 关闭按钮退出。
- 每人可选“自动”“采集优先”“建造生产优先”。采集优先：打捞/收网 → 钓鱼 → 施工 → 制水/烤鱼；建造生产优先：施工 → 制水/烤鱼 → 打捞/收网 → 钓鱼。偏好工作不足时自动补位；修改偏好会安全释放工作和预留材料，饮食完成后再切换。
- 蓝图、救援、打捞物、收集网及设施操作位只允许一名船员领取。同一操作位不能同时使用；不同操作位可以同时作业。开局仍只有一根共用鱼竿，未增加第二根。各人消耗独立，饥渴不足只降低自己的效率，顶部需求条在两人时显示平均值，详情在分工面板分别展示。
- 两人沿已建甲板四邻格寻路，通行时采用小幅位置错开，可互相穿行；当前不加入互相堵路和碰撞等待。设施的脚下占用检查包含两人，防止把任一船员封在设施内。
- 存档保存每人的稳定 ID、名字、偏好、甲板位置、饱腹、水分、精力与未完成休息意愿，以及待救生筏的位置、标记、漂流年龄和等待倒计时。读档取消旧领取与预留、恢复名册，未完成工作重新调度；拒绝超员、重复/非法 ID、非法偏好、异常需求、无效落脚点或满员同时带待救生筏的数据。

当前不包含手动移动指令、材料搬运、能力差异或第三名船员。

### 床铺、精力与自动休息

- `B` → 生活设施 → 基础床铺，或按 `H` 进入放置。床铺开局已知，消耗 **6 木材 + 1 废料**，占一格正式甲板，旁边保留一格上下床操作位；`R` 旋转。放蓝图、预留建材、船员施工、通路检查、搬移与全额返料拆除均沿用设施流程。
- 每人独立精力初始 85。行走、打捞、施工、救援、钓鱼和生产时每秒消耗 0.12，待命与饮食时每秒消耗 0.02。床上休息不消耗精力；暂停停止消耗和恢复，倍速同步加快。
- 精力降至 30 或以下，有可达空床时会安全释放当前工作和预留材料，走到操作位上床。每秒恢复 3，达到 90 后起床，继续按工作偏好接任务。恢复速度不受疲劳效率影响。暂时没有可用床时继续工作，低精力只降低自己的效率。
- 每张床与上下床位置只允许一人领取，赶路期间也保留床位。两张床可让两人同时休息，一张床供两人轮流使用；没有免费附送床铺。睡眠以横躺姿态和 `Z z` 表现，逻辑寻路位置保留在上下床的安全甲板上。
- 饮食可中断休息。恢复到一半起床吃饭、床铺被搬移/拆除或读取存档后，会保留已恢复精力和休息意愿，再有床可用时继续恢复至 90。修改工作偏好不会打断本次休息，醒后采用新偏好。
- 选中床铺显示休息者、恢复进度和单人床位信息。搬移、旋转和拆除会先安全唤醒使用者，取消搬移后可继续休息；拆除按原建造用料全额返还。
- 经营 HUD 新增紫色精力条与数值，两人时显示平均精力；`C` 分工面板分别显示每个人的精力、寻找床位/休息状态和恢复进度。
- 存档保存各人精力与未完成休息意愿，床铺沿用设施位置、朝向、施工进度和历史用料存档。床位领取对象不序列化，读档后重新分配，防止床位被旧任务锁住；异常精力、无效床铺占地/操作位或在床铺内藏收集网物资的数据会被拒绝。

当前按精力安排休息，尚未加入固定作息或床位归属。

### 土豆种植与自动照料

- `B` → 生活设施 → **土豆种植箱**，或按 `J` 放置。开局已知，占一格正式甲板，消耗 **4 木材 + 1 废料**，相邻保留操作位；`R` 旋转。沿用船员蓝图施工、材料预留、通路和脚下占用检查，建成后阻挡寻路，不计入装饰舒适度。
- 开局提供 2 份土豆作种薯，补给箱额外提供 1 份。每轮先由船员播种：到达操作位预留 1 土豆，默认工作 2 秒后消耗并进入“已播种/待浇水”。未完成播种取消时完整释放种薯，尚未播下的种薯不计入作物。
- 浇水为独立工作，默认 1.5 秒，消耗 1 淡水后开始生长。浇水会给每名口渴船员留出一份饮用水；进行中若出现新的饮用需求，也会释放浇水预留，让饮水优先。缺水时种苗保留并等待，不会凭空生长或死亡。
- 浇水完成后默认 **60 秒经营时间**成熟，不再占用船员。模型从幼苗逐渐长大，成熟时显示土豆。暂停冻结工作与生长，倍速同步加快；成长本身不受船员效率影响，播种、浇水和收获受各人工作效率影响。
- 成熟后由船员工作 2 秒收获 **3 份土豆**，完成时一次入库并清空当前作物。等待收获不提前奖励；库存溢出时保留成熟作物，稍后再收，重复领取或回调不能重复结算。
- 默认连续种植。选中种植箱，使用“停/种”按钮切换：关闭只停止新播种，当前作物仍会浇水、生长、收获，之后保持空箱。两人可在不同操作位并行照料，同一个箱子或同一个操作位始终只能一人工作。
- 自动偏好把成熟作物视为采集工作，在手动打捞/收网之后收获；播种和浇水归入生产工作，默认在施工后、制水/烹饪前执行。生活需求、休息和救援保持原优先级，工作偏好不足时补位。
- 有启用连续种植的已规划/已建种植箱时，自动烤土豆在接新批次前保留 **1 份种薯**；两座烤架同时工作也不能用掉这份种薯。关闭连续种植后释放这项保留，既有已开工批次可完成。熟食目标由熟鱼与烤土豆共用，进食优先使用熟鱼，缺少熟鱼时可吃烤土豆。
- 种植箱可带作物免费搬移、旋转，搬移预览期间暂停生长，取消保留原位置和作物。箱内有作物时不能拆除，先关闭连续种植并等待收空，再按原建造用料全额回收；移动不会返还已消耗的种薯或浇水。
- 左侧新增土豆与烤土豆库存卡片，提供图标、数量、可用/预留短条和悬停说明，并显示熟食合计/目标；顶部五种资源保留原位置。设施面板显示播种/浇水/成熟状态、生长进度、剩余时间及连续种植开关。生长阶段、土豆库存和开关接入版本 6 存档，未完成工作领取与预留在读档后重新调度。
- 读取时拒绝未知作物阶段、异常进度、未完成箱子中已种作物、成熟与进度不匹配、非种植箱携带作物、负土豆/烤土豆库存等数据，验证完成前不改动当前游戏。

当前先提供土豆一种作物，每轮浇水一次，尚未加入种子品种、肥料、天气影响、枯萎或离线生长。

### 装饰与营地舒适度

- `B` → 生活设施中提供床铺、**海岛盆栽、编织地毯、营地装饰灯、土豆种植箱**五张开局已知图纸。盆栽消耗 2 木材/1 废料，地毯 3 木材，装饰灯 2 木材/2 废料；均先放蓝图，由船员到格子中施工，开始时预留用料、完成时结算。开局不附送装饰。
- 三种装饰每件占用一格正式甲板，并保持可通行。盆栽与灯具放在格子角落，地毯铺在地面；可以布置在功能设施的上下床/生产操作位或船员所在格。每格只能有一个设施或装饰，不能把地毯直接叠在床铺/烤架占地上。装饰无需额外保留相邻操作位，窄通道和向外扩建仍可经过装饰格。
- 装饰使用现有选中、`R` 旋转、免费搬移、取消搬移和拆除返料流程，返还原建造用料。移动床旁地毯不会打断床上的休息。装饰蓝图、施工目标和施工位置沿用船员领取锁，避免两人重复施工。
- `ComfortManager` 由 `GameManager` 读取 `ComfortConfig` 初始化。只统计已建成的三种装饰，默认每种第一件贡献 20 分，之后同类按前一件的 50% 递减：20、10、5、2.5……，鼓励多种搭配；床铺和开局环境灯不计入装饰贡献。营地总舒适度最高 100。
- 床上精力恢复速度乘以 `1 + 舒适度 / 100 × 25%`，最多提高 25%。例如三种装饰各一件得到 60 分，恢复从每秒 3 提高到 3.45。加成在休息中随已建装饰变化立即更新，暂停时仍不恢复精力。
- 搬移预览保留原位装饰和贡献，确认或取消不会增加贡献；回收后按剩余同类数量重新计算，重复操作不能叠加加成。舒适度不单独写进存档，读档后从已建布局计算，避免缓存分数或加成重复累积。
- 左侧舒适度卡片或 `V` 打开 `UIPop_Comfort`：显示总分、休息加成、每种数量、同类贡献和下一件预计增加的分数。与船员面板互相切换，使用 Pop 层、`cache=true`，同名 AA 地址放入 `UI` 分组。打开时拦截世界指令，模拟按当前暂停/速度继续运行；关闭按钮或 `Esc` 退出。
- 选中单件装饰可查看同类总贡献、回收本件会减少的贡献及返料。船员分工面板在休息时显示当前恢复加成。营地装饰灯随现有昼夜平滑亮起/熄灭，夜间提供暖色灯光；暂停和读档沿用经营时钟。
- 存档保存装饰类型、位置、朝向、施工进度和历史用料，并允许船员与功能设施操作位在装饰格上；重复占地、未知类型、没有正式甲板或在装饰内夹带收集网物资的存档会被拒绝。

当前舒适度为全营地共享奖励，尚未加入局部房间、个人喜好、装饰耐久或固定目标。

## 当前实现：海洋预览

使用项目现有的 Built-in Render Pipeline，无需额外水体插件或贴图。

- 独立场景：`Assets/Scenes/OceanPreview.unity`，保留已有 `MainMenu` 场景。
- 浅海使用明亮青绿色，深海使用深蓝色，两者之间柔和过渡；保留三组低幅波浪、稀疏波纹、阳光高光与接触泡沫。
- 水面使用逐像素解析波浪法线，消除粗网格造成的块状反光；细波纹采用交错方向与疏密变化，拉远时按像素尺寸淡出，减少密集划线和闪烁。
- 天空反射、波峰亮部和接触泡沫分别控制，默认深浅海过渡宽度为 24 米。`ReflectionStrength` 调整柔和天空反射，`SunGlint` 调整阳光高光。
- 正交斜俯视相机，平移时海面跟随视野中心，水纹使用世界坐标保持连续。
- `GameManager` 读取配置并依次初始化 `CameraManager`、`OceanManager`，统一驱动更新。
- 波高查询接口 `OceanManager.GetSurfaceHeight`，供后续漂浮物表现使用。

### 浅海与深海

- 当前使用一片可配置的椭圆形浅海区，外侧为深海；边界叠加轻微不规则变化，避免生硬的几何轮廓。
- 水域位置使用固定世界坐标，不随相机、海面网格或波浪动画移动。
- 在 `Ocean_Default.asset` 中调整 `ShallowCenter`（世界 X/Z 中心）、`ShallowRadii`（X/Z 半径）、`DepthTransitionWidth`（过渡宽度）与 `BoundaryVariation`（边界起伏）。
- 默认浅海水深 3 米、深海水深 45 米，可分别通过 `ShallowDepth` / `DeepDepth` 调整；过渡区水深连续变化。
- `OceanManager.GetRegion` 返回 `OceanRegion.Shallow` 或 `OceanRegion.Deep`，以过渡权重 0.5 为分类边界；`GetDeepWaterBlend` 返回 0～1 的深海权重，`GetWaterDepth` 返回配置水深。
- 当前水深来自程序化分区数据，用于颜色表现和后续玩法查询，尚未创建实际海床地形。

### 预览方法

1. 打开 `Assets/Scenes/OceanPreview.unity`，点击 Play。
2. 使用 `WASD` / 方向键平移，或按住鼠标中键拖动。
3. 鼠标滚轮缩放，`Q` / `E` 旋转，`Home` 恢复默认视角。

## 体验定位

- 以生产、布局、扩建和装饰为主要乐趣，营造轻松的海上生活感。
- 不设置强制终点、限时通关或必须完成的主线目标。
- 通过新设施、生活改善、木筏扩建和新船员，让玩家自然形成自己的小目标。
- 从单人开局，逐渐发展成少量船员共同生活的小社区。
- 生存压力保持温和，给玩家留出规划、布置和欣赏海景的时间。

## 核心循环

**收集漂浮物 → 建造设施 → 生产食物和淡水 → 稳定生活 → 扩建木筏 → 招募船员与改善布局。**

典型体验：玩家发现木材不足，增加收集设施；资源充裕后扩建甲板、改善生产；接纳新船员后重新分配工作，再布置菜园、休息角和住处。

## 视角与操作

- 采用斜俯视角与正交相机，支持缩放和旋转。
- 玩家下达工作指令，船员自动前往目标位置执行任务。
- 点击漂浮物安排打捞，点击设施管理生产，使用建造界面放置和调整建筑。
- 支持暂停和倍速，方便从容规划。
- 保持镜头平稳，通过海面、漂浮物和环境表现漂流感。
- 当屋顶或前墙遮挡角色和工作区域时，采用淡化等方式保持可见性。

## 自由扩建与布局

- 使用统一尺寸的方格甲板，玩家自由决定木筏形状和设施位置。
- 可以拼出长条、庭院或相连的小平台，不采用整间厨房、卧室等固定功能模块扩建。
- 第一版先聚焦单层布局。
- 建造时提供网格吸附、透明预览，以及可放置或不可放置的提示。
- 建筑支持移动，拆除返还建造材料。
- 新建采用蓝图施工流程：放置蓝图后，由船员自动搬运材料并施工，完工后转为正式建筑。
- 暂停期间也可以放置蓝图，恢复运行后继续执行施工任务。
- 移动已建好的设施立即完成，不重复施工，方便调整布局。
- 收集网、捕鱼设施等需要接触海水，布置在木筏边缘。
- 生产设施、仓储和生活设施自由安排在甲板上。
- 船员需要可通行的道路，摆放设施时应考虑通路。
- 搬运距离影响效率，仓储与工作区的相对位置具有经营价值。
- 初期保持布局规则简单，复杂管线和电路系统留待后续讨论。

## 收集与生产

- 前期由玩家安排打捞附近的漂浮物，后续通过收集网等设施提高自动化程度。
- 基础生产包含捕鱼、净水、种植和烹饪。
- 生产以自动执行为主，玩家可以设置库存目标，例如保持一定数量的淡水和食物。
- 船员在材料和工作条件满足时自动补充库存，减少重复点击。
- 支持调整打捞、搬运、生产和建造的工作优先级。

初期资源种类保持精简：

| 资源 | 主要用途 |
| --- | --- |
| 木材 | 甲板、家具、燃料 |
| 废料 | 工具、设备建造与升级 |
| 纤维 | 绳索、收集网、床 |
| 食物 | 满足船员进食需求 |
| 淡水 | 满足船员饮水需求 |

具体配方、消耗量、生产时长和储存容量尚未确定。

## 船员与生活

- 从一名船员开始，后续逐步招募少量船员。
- 玩家管理工作分配与优先级，船员自动执行任务。
- 基础生活需求包括食物、饮水和休息。
- 缺乏食物和淡水时降低工作效率，初版不设置饥饿或缺水死亡。
- 船员空闲时可以吃饭、休息、看海或照顾植物，让木筏呈现生活气息。
- 性格、关系和更复杂的社交系统留待后续讨论。

## 漂流与海上事件

- 木筏自动漂流，玩家主要决定是否停靠和探索。
- 后续可以加入漂流宝箱、商船、鱼群和小岛，提供资源与经营机会。
- 天气以改变景色、氛围和产出为主，保持轻松的整体节奏。
- 风暴和探索的具体机制尚未确定，不作为首版核心依赖。

## 美术方向

整体采用**温暖、清爽、明亮的风格化 3D**，使用低多边形造型、简化材质、柔和光照和清晰轮廓，表现玩家亲手经营出来的海上家园。

| 部分 | 视觉设定 |
| --- | --- |
| 海水 | 蓝绿色，宽而柔和的波纹，木筏边缘少量白色泡沫 |
| 木筏 | 蜂蜜色木板、圆木浮筒、绳索连接，方格模块容易辨认 |
| 建筑 | 木架、帆布棚和回收材料，逐步升级成精致小屋 |
| 人物 | 稍大头身比、简洁轮廓，搬运、捕鱼和休息动作清楚易读 |
| 植物与装饰 | 饱满的绿色植物，搭配地毯、旗帜、遮阳棚、吊床和小灯 |
| 光照 | 白天明亮柔和，傍晚偏金色，夜晚用暖灯照亮生活区 |

### 美术与建造的配合

- 统一甲板与设施的尺寸规则，保证不同形状的木筏组合自然。
- 栏杆、立柱和绳索沿甲板边缘衔接，强化手工搭建的感觉。
- 保留木材与海水的基本质感，控制木纹、绳结和碎波的细节密度。
- 拉远镜头后仍需区分道路、船员、资源与设施，优先保证经营信息可读。
- 装饰也应具有独立吸引力，让玩家愿意为舒适和美观投入资源。
- 已讨论的概念图用于说明美术方向，不代表实际游戏画面或最终细节密度。

## 代码框架约定

以下约定用于指导代码和 UI 资源制作。目前已建立游戏流程、相机、海洋/昼夜/鱼群、建造/设施操作、船员、库存/掉落、打捞/钓鱼、烹饪/净水、需求、时间、存档及 UI 的 MVC 框架；具体内容以“当前实现”为准。

### 游戏整体流程

- 游戏整体流程由 `GameManager` 统一控制，包括初始化、进入游戏、暂停、恢复及退出等流程。
- 每个系统由一个对应的 `Manager` 统一管理，`GameManager` 负责协调这些 Manager，具体玩法逻辑由对应的 Manager 及其内部模块实现。
- 配置读取和各系统初始化由 `GameManager` 统一组织：读取配置后，根据系统依赖顺序创建或获取对应 Manager，并传入所需配置完成初始化。
- 各 Manager 不依赖不确定的 `Awake` / `Start` 调用顺序自行完成跨系统初始化；依赖系统就绪后，再进入游戏运行流程。
- UI 通过 Controller 发起流程请求，由 `GameManager` 统一执行流程切换。

### 系统 Manager 职责

各系统按实际需要逐步建立，职责划分示例：

| Manager | 负责内容 |
| --- | --- |
| `UIManager` | UI 注册、加载、层级、缓存和面板生命周期 |
| `CameraManager` | 斜俯视相机、平移、旋转和缩放 |
| `OceanManager` | 海洋配置、波浪更新、海面跟随与波高查询 |
| `ResourceManager` | 经营资源库存、资源增减与材料消耗 |
| `SalvageManager` | 漂浮物生成与漂流、打捞标记、任务领取与收集 |
| `FishingManager` | 开局鱼竿、钓位与使用权、钓鱼开关、单次渔获结算 |
| `BuildManager` | 网格、甲板、设施布局、蓝图与施工状态 |
| `FacilityManager` | 已建设施的选择、高亮、搬移预览与拆除确认 |
| `CollectionNetManager` | 自动拦截、四件暂存、领取与逐件收取结算 |
| `ProductionManager` | 生产配方执行、库存目标和生产进度 |
| `CrewManager` | 船员、工作安排和生活需求 |
| `RescueManager` | 救生筏出现、标记、接应与招募 |
| `NeedsManager` | 各船员独立的饱腹、水分、效率与饮食预留 |
| `RestManager` | 床位领取、到床休息、恢复精力与中断释放 |
| `ComfortManager` | 已建装饰贡献、重复递减、全营地休息加成与装饰灯昼夜表现 |
| `FarmingManager` | 种植箱领取、播种浇水、生长收获、饮用水与种薯保留 |
| `TimeManager` | 经营时间、暂停和倍速 |
| `SaveManager` | 游戏运行数据的保存与恢复 |

- 各业务系统的运行数据由对应 Manager 管理，UI 通过 Controller 读取数据或发起操作。
- `UIModel` 保存面板需要的界面状态，不作为资源库存、船员或建筑数据的唯一存储位置。
- 配置格式、各 Manager 的具体接口和依赖顺序在实现时细化。

### UI 的 MVC 结构

UI 框架采用 MVC，创建以下三个基类：

| 基类 | 职责 |
| --- | --- |
| `UIView` | 负责界面显示、控件引用和交互事件暴露；在 View 中配置面板所属的 `UILayer` 和 `bool cache` |
| `UIController` | 连接 View 与 Model，处理界面交互、调用业务系统并协调界面刷新 |
| `UIModel` | 保存面板所需的界面数据和状态，不持有 UI 控件引用 |

- 具体面板的 View、Controller 和 Model 分别继承对应基类。
- View 负责表现，业务处理通过 Controller 协调，避免把经营逻辑直接写入 View。
- 面板初始化、打开、关闭和销毁时，统一处理 MVC 绑定、事件订阅与清理。

### UI 层级

定义 `UILayer`，从下到上固定为四层：

| 层级 | 用途示例 |
| --- | --- |
| `Bottom` | 底层背景、基础界面 |
| `Common` | 常规功能面板，例如主菜单、经营界面 |
| `Pop` | 弹窗，例如确认框、详情弹窗 |
| `Top` | 顶层提示、加载遮罩等 |

- 每个面板在 `UIView` 中选择所属层级，`UIManager` 读取该配置并将面板挂到对应层级节点。
- 面板的名称层级与 `UIView` 中配置的层级必须一致。
- 层级顺序由 `UIManager` 统一维护，不由具体面板自行建立层级根节点。

### UIManager

- 在 `UIManager` 中统一注册面板，以及面板对应的 View、Controller、Model 和 AA 地址。
- 统一提供面板的创建、打开、关闭、查询和销毁入口，管理面板实例及其生命周期。
- 创建面板时通过 AA 加载预制体，读取 `UIView` 的层级配置，再挂载到对应 UI 层。
- 关闭面板时读取该 `UIView` 的 `cache` 值，决定隐藏缓存还是直接销毁。
- 统一初始化和绑定 MVC，销毁时解除事件绑定并释放对应的 AA 实例及资源引用。
- 具体面板通过 `UIManager` 管理其他面板，不自行加载、实例化或销毁其他面板。

### UI 缓存与关闭行为

- 在 `UIView` 中添加可在 Inspector 配置的 `bool cache` 字段，由每个面板自行选择是否缓存。

| `cache` 值 | 关闭面板时 | 再次打开时 |
| --- | --- | --- |
| `true` | 隐藏面板，保留实例、对应 MVC 对象及所需 AA 资源引用 | 复用缓存实例，刷新数据并显示 |
| `false` | 直接销毁面板，清理 MVC 和事件，释放对应 AA 实例及资源引用 | 重新通过 AA 加载并创建 |

- 两种关闭路径都执行关闭生命周期，停止当前界面的交互与显示期监听；再次打开时恢复必要绑定，避免重复订阅。
- 隐藏缓存与销毁明确区分，隐藏时不执行最终销毁清理，也不提前释放仍被缓存实例使用的 AA 资源。
- 显式调用销毁或统一清理缓存时，不受 `cache` 值限制，仍需完整释放对应对象和资源。

### UI 预制体与命名

- 每个 UI 面板都制作一个独立预制体。
- UI 面板预制体统一放在 `Assets/Art/Prefabs/UI/` 文件夹下。
- 预制体根节点挂载该面板对应的 `UIView` 派生组件，并配置所属层级与 `cache` 值。
- 面板名称与预制体名称统一采用 `UI` + 层级 + `_` + 名字的格式。

例如：

| 面板名称 / 预制体名称 | 所属层级 | 用途 |
| --- | --- | --- |
| `UICommon_MainMenu` | `Common` | 主菜单 |
| `UICommon_Management` | `Common` | 经营主界面 |
| `UIPop_Confirm` | `Pop` | 确认弹窗 |
| `UITop_Loading` | `Top` | 加载界面 |

以上名称用于说明命名规则，不代表已经创建相应面板。

### AA 加载规范

- UI 面板统一通过 Addressables（简称 AA）加载。
- 在 AA 中建立名为 `UI` 的资源分类，以 `UI` 分组统一管理 UI 面板预制体；预制体文件统一位于 `Assets/Art/Prefabs/UI/` 文件夹。
- AA 地址直接使用预制体名称，不包含目录、扩展名或额外前缀。
- 例如 `Assets/Art/Prefabs/UI/UICommon_MainMenu.prefab` 的 AA 地址为 `UICommon_MainMenu`。
- 预制体名称和 AA 地址保持唯一；重命名时同步更新注册信息、AA 地址和引用。
- AA 加载、加载失败处理与资源释放由 `UIManager` 统一管理。

当前项目已添加 Addressables 1.22.3，并建立 UI 分组与建造面板地址。
